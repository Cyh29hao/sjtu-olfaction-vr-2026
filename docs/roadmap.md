# 从初稿到课堂

计划于 2026 年 11 月 10 日前后正式启动组内协作，第十一周汇报。具体上台日期与顺序待确认，提交按截图正文的 2026-11-25 17:00 控制。以下是工作顺序，具体组内节点由组长协商。

## 统一首稿

- [x] 听众目标已明确：能解释虚拟嗅觉、举出一种实际应用方式，并能检查宣传证据。
- [x] 陈云海选定“闻花贯穿”的叙事与蓝绿青春模板。
- [x] 广泛文献地图和模板比较已形成，逐篇区分题录、摘要与正文核读。
- [x] 发布完整 PPTX／PDF、全场口播、来源与问答材料。
- [x] 同步各组独立文稿、核改入口与统一合稿办法。

初稿的完成状态以 [仓库首页](../README.md) 的实际可打开文件为准。生成文件、视觉检查、人工复核与真人试讲分别记录。

## 各组精修

- [ ] 各组建小群，推选一位 GitHub 代表，由陈云海核对账号并邀请。
- [ ] 各成员先看全场，再由组长安排本组的实际工作。
- [ ] 核查本组原始来源、关键数字、图示与结论；记录原文位置和复核者。
- [ ] 修改本组文稿、口播与图；直接改 PPT 时使用本组副本并同步来源。
- [ ] 涉及跨组术语、交接结论或用时，组长和第 0 组一起协调。
- [ ] 本组代表汇总提交，保留每个人的具体贡献。

各组可换例、补证和重写。主线、证据标准、交接问题与全场时长共同维护；无需为了保持初稿而留下解释不清的内容。

## 统一合稿

- [ ] 第 0 组检查全场是否仍围绕一个问题，删掉重复，补齐断层。
- [ ] 把文稿或 PPT 改动同步进内容源，统一术语、版式、来源标记与讲稿，重新生成总 PPTX／PDF。
- [ ] 逐页查看实际渲染，核对图表、文字、备注与口播一致。
- [ ] 各组确认自己的意思准确进入总稿，重新检查相邻段落。
- [ ] 若有视频或动画，按实际播放方式检查，并保留静态讲法。

## 课堂前验收

- [ ] 找未参与制作的同学复述：虚拟嗅觉是什么、怎样实现、能怎样应用、看宣传先问什么；保留实际反馈。
- [ ] 主讲者完整试讲，记录含换人、翻页与媒体的总用时，控制在 12 分钟以内。
- [ ] 确认最多 4 人上台，另留 2–3 分钟互动。
- [ ] 每位主讲者熟悉本段口播、相邻转场与常见追问。
- [ ] 每位成员确认自己的实际贡献，PPT 最后一页列出分工。
- [ ] 小组长完成 Canvas 上传，检查实际文件可打开并保留提交回执。

首稿阶段的 AI 检查不能代替成员人工复核、真人试讲或 Canvas 提交。这些项目只有实际完成后才勾选。
