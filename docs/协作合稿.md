# 各组怎样改，整场怎样合

我们要保留一场汇报的完整感，也让三个小组能够各自推进。做法是：**共同维护一条故事线，各组拥有自己的内容；总 PPT 的版式与转场由第 0 组统一。**

## 一起维护的部分

全场问题是：在虚拟花园里闻一朵花，需要怎样的技术？多出来的气味，在什么任务中有用？

| 模块 | 本组负责 | 交给下一段什么 |
| --- | --- | --- |
| S 科学原理 | 用听众能懂的方式解释嗅觉所需的基础与复现难点 | 第二组需要解决的技术问题 |
| T 技术与设备 | 跟随一次体验讲控制、释放、同步和残留，讲清一个代表装置 | 装置实际具备的能力，以及“做到之后有什么用”的问题 |
| A 多感官与应用 | 用精选研究检验具体收益，区分测量结果和适用边界 | 有依据的前景与宣传判断 |
| 第 0 组开场与收束 | 提出同一个体验问题，最后让听众用证据回答 | 一句能带走的解释和一个会使用的判断方法 |

开场中的花园是叙事设定。讲到真实装置和实验时，明确回到对应论文的装置、任务与参与者；不要让听众误以为所有研究都在同一个花园里完成。

### 只固定必要的交接

- S 到 T：听众已理解必要科学基础，可以开始问“用什么材料、怎样送到鼻子”。
- T 到 A：听众已理解装置能做什么，可以开始问“在哪种任务中，多出来的气味有价值”。
- A 到收束：听众能区分能力、体验、任务与健康结局，再用相同问题评价具体宣传。

这些是共同维护的意思，逐字台词可以润色。术语按全场统一讲法使用；若某个词需要更正，提出改动并同步相关组，避免各讲各的定义。

## 各组可以自由改什么

解释顺序、例子、论证、图示和口播都可以改，甚至可以重写。先确认改后的版本仍回答本组问题，来源支持表述，用时容得下。

| 变化 | 为什么需要一起看 | 怎样交代 |
| --- | --- | --- |
| 更换贯穿体验或主案例 | 可能影响前后段已经铺垫的对象 | 新旧例子、受影响的段落、建议怎样衔接 |
| 改变共用术语或核心结论 | 别组可能仍沿用旧说法 | 原句、修改依据、需同步的位置 |
| 明显增加用时或页面 | 全场只有 12 分钟 | 增加了什么，建议删减哪里 |
| 删除关键来源或更换实验 | 下游判断可能失去依据 | 新证据支持到哪一步，哪些结论随之调整 |

只改本组一句口播或修正一条引文，直接提交即可，不增加额外审批。

## 文件安排

各组先读、先改 `本组文稿.md`，意见可写进 `建议.md`。想直接改页面，可以使用本组 PPTX；连同对应口播、来源一起交回。整合者将确认后的修改同步到 `content.json`，从同一份内容生成本组与全场版本，减少画面、口播和引用各有一套的情况。

| 目录 | 用途 |
| --- | --- |
| `groups/01-science/` | S 模块，科学原理及来源补充 |
| `groups/02-technology/` | T 模块，设备实现及来源补充 |
| `groups/03-applications/` | A 模块，效果研究及来源补充 |
| `groups/00-integration/` | 开场、收束、跨组衔接与合稿记录 |
| `research/`、`references/` | 文献地图、原始入口和结论核查 |
| `release/v1/` | 当前统一版本及各组 PPTX／PDF、口播与问答 |

优先使用稳定模块标识和原句定位，避免每次增删页都重新解释页码。总稿的页码由合稿后确定。组员无需安装构建工具，也无需理解 JSON。

## 为什么把视觉合稿集中到第 0 组

各组独立文本可以逐句比较，互相影响较小。PPTX 的页面修改很难自动合并，多人同时改同一份总稿容易覆盖。平时各组编辑自己的文件，第 0 组把确认后的改动合入并统一版式和转场；各组再检查意思有没有改变。

要改布局时，交本组副本或标注截图即可；要改总稿时先协调编辑时段。整合者保留原稿，明确采用哪些修改，并同步内容源，避免下一次生成时把改动冲掉。

代价是第 0 组仍要负责重新生成与视觉检查。因此各组交稿时尽量把内容、来源和口播一起说明。跨组大改尽早沟通，临近排练时优先修会影响理解或证据的问题。

## 一轮合稿的顺序

1. 本组先把意思讲顺、来源核清，代表汇总修改和贡献。
2. 第 0 组查看变化；涉及另一组时一起确认承接。
3. 合入内容后生成总稿，核对画面、讲稿与来源。
4. 各组确认自己部分的意思及前后转场。
5. 全场试讲，按实际用时取舍，更新公开入口。

## 贡献与人工复核

资料核查、文稿改写、图示、PPT、口播、试讲反馈和组内组织都可以是实际工作。记录具体做了什么及对应位置，由本人确认。初稿中的组长和组别是已知安排，不能提前写成每位同学已完成的贡献。

人工复核记录姓名、日期、查阅的原文位置和支持的具体表述。AI 检查可以辅助定位，单独标记；“已由 AI 检查”不能写成“成员已人工复核”。最终提交前将实际贡献汇入 PPT 最后一页。
