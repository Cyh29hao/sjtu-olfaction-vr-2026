# 各组怎样改，整场怎样合

初稿帮助大家理解全场方向，之后交给各组精修。**各组可以换例、改图、补证和重写，第0组把确认的内容合入总稿。** 本轮以[v3](../README.md)为准；已讨论的方向见 [叙事与合稿基准](叙事与合稿基准.md)。

## 共同维护的推进

科学基础连续解释后再讲技术；技术展开一套装置的完整过程；应用展开一个任务与结果，短对照帮助理解效果；最后回到个人体验、使用与宣传判断。闻花承担开场和装置解释，进入应用时会换到新的真实任务。

| 负责组 | 当前参考范围／用时 | 交给下一段什么 |
| --- | --- | --- |
| 第一组，第一章 | S01–S02，2分20秒 | 已理解嗅觉基础，装置应当怎样提供并控制刺激？ |
| 第二组，第二章 | T01–T03，3分10秒 | 已理解一次受控嗅闻，这样的能力适合什么任务？ |
| 第三组，第三章 | A01–A03，3分20秒 | 已理解任务、结果和测量边界，自己怎样尝试和判断？ |
| 第0组 | 开场O01–O02，1分钟；第四章C01–C02，1分40秒 | 开场说明动机与路线，结尾给出入口和判断方法 |

本稿12页主讲，内容预算690秒，另留30秒换人和停顿；后有8页备课／参考及末页分工。范围、用时与具体讲法是当前参考，随内容和真人试讲调整，最终总讲述12分钟。

## 合稿看效果

合稿时一起看五件事：目录和标题能否说明推进，上一段的问题是否被接住，每个案例为什么出场，结论是否对应测量，四个人是否讲得顺且守时。具体说明见 [合稿基准](叙事与合稿基准.md#合并时用这些问题检阅)。

这些问题帮助比较不同方案。某个例子、图示或讲法能让人理解得更好，就可以采用；初稿的页数、句子和版式本身没有优先权。

## 各组的修改范围

| 可以自主推进 | 涉及相邻组时一起说明 |
| --- | --- |
| 必要概念、讲法与机制图 | 交给下组的要求或术语怎样变化 |
| 代表装置、流程图与工程证据 | 科学基础如何接到实现，应用还能使用哪些能力 |
| 应用任务、比较研究、数据图与分析 | 新案例承担什么作用，结尾能作什么判断 |
| 引入方式、体验入口与整体节奏 | 与三组确认科学表述、衔接和全场用时 |

只润色一句口播或修正一条引文，直接提交即可。较大换例或重写时，把上下段需要调整的地方一起说明，减少合稿时返工。

## 组员怎样交，整合者怎样合

先改 `本组文稿.md`，意见可写进 `建议.md`。也可以直接改本组PPTX副本，连同对应口播与来源一起交回。整合者将确认的修改同步进内容源，再更新本组与全场版本；组员无需安装构建工具或理解JSON。

| 目录 | 用途 |
| --- | --- |
| `groups/01-science/` | 第一章文稿、建议与来源补充 |
| `groups/02-technology/` | 第二章文稿、建议与来源补充 |
| `groups/03-applications/` | 第三章文稿、建议与来源补充 |
| `groups/00-integration/` | 开场、第四章与全场衔接 |
| `release/v3/` | 本轮各组和全场版本、口播与备课材料 |
| `research/`、`references/` | 文献地图、原始入口与来源记录 |
| `release/v1/`、`release/v2/` | 保留的历史版本 |

反馈优先写S01、T02、A03等模块标识和原句，可附当前页码；增删页后仍能定位。

文本改动容易逐句比较，PPTX页面很难自动合并。平时各组编辑自己的副本，第0组合入并统一视觉和转场；想直接改总稿时，先协调编辑时段，保留其他人的修改。

集中视觉合稿的代价是第0组仍要更新并查看完整画面。各组交稿时把文稿、页面、来源和交接变化放在一起，整合者同步内容源，避免下一次生成时丢失修改。

## 一轮合稿

1. 本组把意思讲顺、来源核清，代表汇总修改和贡献。
2. 跨组变化一起确认交接与用时。
3. 第0组合入，统一更新页面、讲稿和来源。
4. 各组确认本组意思及前后承接。
5. 全场试讲，按真实反馈取舍，再更新公开入口。

## 复核与贡献

资料核查、改写、图示、PPT、口播、试讲反馈和组内组织都可作为实际工作。写清做了什么及对应位置，由本人确认。组别和职务是已知安排，实际贡献另行记录，最后汇入PPT末页。

人工复核记录姓名、日期、原文位置和支持的表述；AI检查单独标记。演示材料说明研究者做过什么，小组自己的复核、制作和演示在实际发生后记录。
