# 各组怎样改，整场怎样合

**共同维护一条故事线，各组拥有自己的内容；总 PPT 的版式与转场由第 0 组统一。** 本轮精修以 [v2](../README.md) 为准，v1 保留供比较。

## 共同维护的主线

从一项真实的 VR 闻花演示出发，先解释鼻子需要什么刺激，再看预装材料怎样在合适的时候释放。装置已经能组织一次嗅闻，接下来问它适合什么任务：先看酒窖辨香，再明确换到放松目标，最后讨论实际使用和宣传判断。

| 负责组 | v2范围与预算 | 本组讲什么 | 交给下一段什么 |
| --- | --- | --- | --- |
| 第 0 组 | O01–O02、C01–C02，2分30秒 | 闻花演示提出问题，最后回到实现、用途与判断 | 一场能跟上的故事与能带走的方法 |
| 第一组 | S01–S03，2分15秒 | 分子、受体响应、预装材料与释放要求 | 材料选好后，怎样按动作控制释放 |
| 第二组 | T01–T03，2分40秒 | 近鼻发生器、靠近触发、停止后余味散去 | 一次嗅闻能受控，适合用来完成什么任务 |
| 第三组 | A01–A04，3分20秒 | 酒窖辨香；换到放松时看对照与结果；实际使用 | 不同用途该看什么结果，怎样判断加香的价值 |

主讲共 14 页，内容预算 645 秒，另留 75 秒换人和停顿。预算是当前设计，可随内容与真实试讲调整；总讲述保持在 12 分钟内。AI 气味预测与装置形态比较放在备课，不作为各组额外的主讲任务。

## 只固定必要的交接

- **S 到 T：** 已选好真实材料，并提出强弱、时机和退味要求。接下来讲材料放在哪里，程序如何控制它。
- **T 到 A：** 已解释一套装置怎样完成一次嗅闻。接下来进入辨香练习，看场景、气味与反馈如何配合。
- **A 内部换目标：** 酒窖里的闻香是题目本身；放松研究是在相同程序中增加气味。明确目标变了，再解释为什么要换比较方法。
- **A 到收束：** 已见过具体任务和对照结果，再回到宣传的比较对象、测量结果与使用条件。

共同维护的是这些意思，逐字台词可以改。开场和近鼻装置的研究、手柄酒窖研究、放松研究是不同来源；讲述时让听众知道何时换了装置、场景与研究对象。

## 各组可以自由改什么

解释顺序、案例、图示、论证和口播都可以改，甚至可以重写。先确认改后的版本仍回答本组问题，来源支持表述，听众能跟上，用时容得下。

| 变化 | 需要一起看的原因 | 交稿时说明 |
| --- | --- | --- |
| 换贯穿体验或主案例 | 会影响前后已铺垫的对象、动作或任务 | 新旧例子、受影响段落、衔接建议 |
| 改共用术语或核心结论 | 别组可能仍沿用旧说法 | 原句、修改依据、需同步的位置 |
| 增加讲述时间或页面 | 全场只有 12 分钟 | 增加内容及准备压缩的部分 |
| 换实验或删关键来源 | 下游判断可能随之改变 | 新证据支持到哪一步，哪些句子要一起改 |

只改一句口播或修正一条引文，直接提交即可。各组无需为普通表达调整另设审批。

## 文件与交稿

各组先读、先改 `本组文稿.md`，意见可写进 `建议.md`；也可以使用本组 PPTX，连同对应口播和来源一起交回。整合者将确认的修改同步进内容源，再更新本组与全场版本。组员无需安装构建工具，也无需理解 JSON。

| 目录 | 用途 |
| --- | --- |
| `groups/01-science/` | S01–S03，本组文稿与核查建议 |
| `groups/02-technology/` | T01–T03，本组文稿与核查建议 |
| `groups/03-applications/` | A01–A04，本组文稿与核查建议 |
| `groups/00-integration/` | 开场、收束与跨组衔接 |
| `research/`、`references/` | 文献地图、原始入口与来源补充 |
| `release/v2/` | 本轮各组与全场版本、口播和备课材料 |
| `release/v1/` | 保留的上一版，供比较 |

反馈优先写 S01、T02、A03 等模块标识和原句，可再附当前页码。增删页后仍能找到改动。

## 为什么把视觉合稿集中处理

各组独立文本可以逐句比较，PPTX 的页面修改很难自动合并。平时各组编辑自己的文件，第 0 组确认改动后统一版式和转场；各组再检查意思有没有改变。想直接改总稿时，先协调编辑时段，保留其他人的修改。

集中处理的代价是第 0 组仍要更新和查看完整画面。因此交稿尽量把内容、口播、来源放在一起，说明跨组影响；整合者同步内容源，避免下一次生成时冲掉大家的修改。

## 一轮合稿的顺序

1. 本组把意思讲顺、来源核清，代表汇总修改和贡献。
2. 涉及相邻组时，一起确认交接与用时。
3. 第 0 组合入，统一更新画面、讲稿和来源。
4. 各组确认本组意思及前后承接。
5. 全场试讲，按实际用时取舍，再更新公开入口。

## 贡献与人工复核

核查、改写、图示、PPT、口播、试讲反馈和组内组织都可以是实际工作。写明做了什么及对应位置，由本人确认。组别和组长身份是已知安排，实际完成的贡献另行记录。

人工复核记录姓名、日期、原文位置和支持的表述。AI 检查单独标记，不能记成成员已经人工复核。最终提交前将每个人的实际贡献汇入 PPT 最后一页。
