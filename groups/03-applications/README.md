## 第一轮先改什么

精选这两个任务讲清，避免加入应用名单。酒窖说明练习已经怎样实现，学习提升要另有证据；换到放松时先讲清目标变化，再检查对照、指标与结果。让听众看懂比较，而不只是记住数字。

接住第二组的受控嗅闻，最后交给第0组比较对象、测量结果与实际使用条件。本组内容、案例、图示和口播均可修改；换例或重写时，说明前后承接和时间受到什么影响，让相邻组和第0组一起调整。

先改 `本组文稿.md`，或把意见写进 `建议.md`。也可以改本组PPTX副本，连同口播和来源一起交回。整合者负责同步内容源，统一更新本组与全场版本；组员无需安装工具或理解JSON。

## 组内怎样分

组长建小群并组织第一轮修改，组内推选一位GitHub代表，把账号发给陈云海核对并邀请。每个人至少完成一项实际工作，工作量、协作形式和发言人自行安排。核源、改解释、做图、改页或试讲都可以共同讨论，保持本组意思连贯。

来源核查使用 [来源笔记模板](../../references/source-note-template.md)，记录原文位置、支持的表述和实际阅读范围。AI检查与人工复核分别记录。各位最后在 [贡献表](../../docs/team.md#实际贡献记录) 确认自己的工作。
